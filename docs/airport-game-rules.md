# 機場需求與虛擬輪候：遊戲規則及資料來源

這份文件描述本輪新增原型；未經版本部署及原生驗收，不代表已交付到現有安裝。

香港機場接單採用真實命名地點與現有車種可通行的有向道路圖。地圖藍色範圍是手繪**遊戲需求區**，並非機場官方邊界、禁區、Uber 實際 geofence 或接客許可。需求、繁忙時段、乘客到達頻率、輪候估計及鑽石優先是可重現的遊戲模型，沒有接駁即時航班、Uber 派單或現實輪候人數。

「立即出發」只導航；到達後臨停，不會自動加入輪候。「前往並加入隊列」才會在實際到達代理入口後領票。上客、現有乘客、預留下一單、已承諾 Elite 預約、長時間休息、能源用盡或交更截止等情況會阻止加入。前往機場途中仍可接正常訂單；接單後按既有訂單流程行車。

## 單人與多人次序

遊戲設的士、私家車、大型車三個獨立池。單人只有自己，沒有捏造其他玩家。多人由房間 authority 分配永久遞增 ordinal，按實際到達時間先後，同時到達用玩家 ID 作確定性排序。鑽石級先於普通級；**同級仍 FIFO**。已派出或已接受的訂單不會被後到鑽石玩家搶走。

票及最後 ordinal 存於既有房間 metadata，冷啟保留。私有 ownState 只帶自己票、排位及人數；公開 room 只有各池總數。斷線 grace 期間保留票，斷線者不獲派單；正常離房、失去資格、停止接單、離隊、轉交更或補給、收更會移除。明確重新加入取得新票，不能保留舊排位。這是原創遊戲政策，並非聲稱還原 Uber 全部例外。

乘客由共享 seed、池別及兩分鐘 slot 產生相同 ID；僅使用領票後到達的乘客。實際派卡前必須重新計算合法上客／送客路線、正常車種價格、能源及交更預算。使用既有五秒實時接單窗口、排他 owner/claim、取消及職業統計，不延長 deadline、不加入免費機場獎金。正常行程完成先入帳；輪候本身不產生收入。沒有模擬未核實的泊車費或補貼。

## 官方資料與模型的界線

[Uber 香港 Airport Queue（2026-05-04）](https://www.uber.com/hk/en/blog/airport_carpark/) 說明虛擬輪候、FIFO 原則及例外、可在區外點飛機圖示看輪候，以及特定服務分池。本文僅以這些可核實概念作設計參考，不照抄其品牌介面。

[Uber HKG 司機資料](https://www.uber.com/global/en/r/airports/hkg/driver-information/) 亦描述指定區域、不同上客地點及虛擬輪候。兩個官方頁面的部分停車優惠／補貼描述不同；本遊戲因此沒有把任何一組現實停車補貼硬套進計價。實際接客資格、機場許可、泊車及平台規則應依當時官方要求，遊戲沒有頒發真實資格。
