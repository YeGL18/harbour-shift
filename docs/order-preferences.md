# 開更前接單類型與盲單設定

這是新更份的遊戲設定，不代表真實平台逐車批准。UberX、UberXL、的士咪錶、咪錶85折及的士預定價分別選擇；車輛座位及資格仍會限制實際可接類型。合資格七座可獨立選UberX及UberXL。專屬預約（ELITE）只可單獨選擇，須通過本遊戲商務課程及使用合資格車款；不與即時普通單混接。沒有開啟任何類型時，不會派發可接訂單，不會憑空增加收入。

0.8.2 的 ELITE 專屬更份於第 3 個遊戲分鐘開始配對首張預約。系統會檢查安全上客路線、油量、預約時間及交更安排。合適的邀請會列在行車畫面的「專屬預約（ELITE）」，由玩家保留後再出發。後續預約沿用低頻抽選。

單人車房設定只影響下一次開更。每更建立時固定接單類型及盲單選擇，恢復存檔也保持原選擇；在車房更改下次設定不會改動現有乘客、預約或未完成更份。新單人存檔使用 `harbour-shift.session.v3`，仍可讀取既有v2及v1；不把新盲單狀態寫回舊程式會讀取的v2命名空間。

新多人房間使用 `orderPolicyVersion:1`，並要求對應客戶端能力標頭。房主只可在等候開更時設定全房盲單；更改後全房重新準備。各玩家只可在等候房間設定自己的接單類型。開更後兩者鎖定。資格由伺服器已核實帳戶判定，不能靠客戶端欄位取得。新房明確的房主盲單選擇優先於舊營運者預設；舊房與舊存檔維持原有規則，不會被追溯升級。

開啟盲單後，目的地及載客路線在乘客上車後才顯示，未完成車資保持隱藏。關閉時使用原有正常訂單介面。只有伺服器確定未執行的版本欄位拒絕，才容許安全協商；明確選了新接單類型或盲單選擇時，不會降級成不受限制的舊規則。

機場仍採單一隊列模型：七座只開UberX時加入私家車池，只開UberXL時加入XL池；兩者都開時沿用XL池，不同時排兩條隊。的士優先使用已開啟的的士預定價池；只開UberX時可使用私家車池。現有機場的士乘客池只產生預定價請求，因此只開咪錶而沒有相容機場類型時，不會加入不可配對隊列。專屬預約或所有類型關閉時也不能加入一般機場隊列。未開啟的類型不會因排隊、預接下一單或自動接單而重新啟用。

本輪純引擎、authority及實際Provider hook測試覆蓋多類型與互斥、容量及資格、同世界候選配對、逐更固定、舊存檔及冷恢復、房主權限、準備狀態重置、版本協商及盲單原始資料遮罩。原生畫面與裝置驗證另由版本QA記錄，不把單元測試當成原生驗收。
